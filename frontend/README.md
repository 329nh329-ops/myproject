全体の要件・設計については以下も参照。

- [要件定義.md](../要件定義.md)
- [docs/機能要件.md](../docs/機能要件.md)

## 技術構成
- TypeScript 6.0系
- React 19.2系（Vite 8.2系）
- Tailwind CSS 4.3系
- Node.js 26系

## ディレクトリ構成

```
frontend/src/
├── App.tsx                 ルートコンポーネント
├── main.tsx                エントリーポイント
├── index.css                Tailwind CSSの読み込み
├── types/
│   └── card.ts              カードの型定義（バックエンドのCardResponseに対応）
├── constants/
│   └── lists.ts             リスト定義（未着手・進行中・完了。バックエンドにリスト一覧APIがまだ無いため固定値）
├── api/
│   └── cards.ts             バックエンドAPI（カードのCRUD・移動・並び替え）の呼び出し
└── components/
    ├── Board.tsx             ボード全体（カード一覧の取得・編集中/ドラッグ中状態の管理）
    ├── BoardColumn.tsx       1つのリスト（見出し・並び替えボタン・カード一覧・カード追加ボタン、リストへのドロップ受け付け）
    ├── CardItem.tsx          1枚のカード（表示、クリックで編集開始、ドラッグ＆ドロップの起点/ドロップ先）
    └── CardForm.tsx          カードの新規作成／編集フォーム（インライン表示、modeで新規・編集を切り替え。編集モードのみ削除ボタンを表示）
```

## 起動方法

バックエンド（PostgreSQL + Spring Boot）を先に起動しておく（[../backend/README.md](../backend/README.md) 参照）。バックエンドは `http://localhost:8080` で動作している前提。

```
npm install
npm run dev
```

起動後、`http://localhost:5173` をブラウザで開く。

## 動作確認

1. `npx tsc --noEmit` で型エラーがないことを確認できる
2. ブラウザの開発者ツールのNetworkタブで `GET http://localhost:8080/api/cards` が200で返っていることを確認できる
3. バックエンドの `data.sql` で投入されるテストデータ（未着手2件・進行中1件・完了1件、計4件）が、ブラウザ上の3リストに正しく振り分けて表示される

## コード品質チェック（lint）

[oxlint](https://oxc.rs/docs/guide/usage/linter.html)（設定：`.oxlintrc.json`）でReactのルール違反（Hooksのルール違反等）を検出する。

```
npm run lint
```

## 現在実装している機能・実装していない機能

[docs/機能要件.md](../docs/機能要件.md) に定義された機能のうち、現時点でフロントエンドに実装済みなのは以下のみ。

| 機能 | 状況 |
|---|---|
| リスト表示（未着手・進行中・完了） | 実装済み |
| カード表示（タイトル・優先度・期限、優先度の色分け、期限切れの強調） | 実装済み |
| カードの新規作成（各リスト下部の「＋タスクを追加」からインライン入力、タイトル必須チェックあり） | 実装済み |
| カードの編集（カードをクリックしてインラインフォームで全項目編集） | 実装済み |
| ドラッグ＆ドロップによるリスト間移動・同一リスト内の並び替え | 実装済み |
| 優先度順・期限順ボタンでの一括並び替え | 実装済み |
| カードの削除（編集フォーム内の「削除」ボタン、confirm()による確認あり、物理削除） | 実装済み |

これで[機能要件.md](../docs/機能要件.md)に定義されたカードのCRUD・移動・並び替え機能はすべて実装済み。画面イメージだけを先に確認したい場合は、DB接続なしでブラウザだけで動く簡易プロトタイプ（[../prototype/](../prototype/)）でも同等の操作感を確認できる。
